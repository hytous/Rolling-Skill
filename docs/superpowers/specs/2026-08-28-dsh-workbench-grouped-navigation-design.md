# DSH Rolling Skill 工作台两级导航设计

## 背景

当前 Rolling Skill 工作台把 14 个页面入口作为同权按钮平铺在标题下方。业务入口、质量闭环和低频维护能力没有层级，用户需要逐个阅读名称才能判断下一步；窄窗口下按钮还会换成多行，进一步削弱顺序和主次。

本次只重构 DSH 插件工作台的信息架构和导航样式，不改变 Case、Skill、安装、评测、Operator 或自动优化的数据与执行行为。

## 已确认方向

采用横向两级导航。第一级只表达四个稳定业务域，第二级显示当前业务域中的页面，并按推荐操作顺序排列。

一级导航为：

1. 概览
2. Case 沉淀与管理
3. Skill 与安装
4. 评测与优化

不采用左侧导航，因为当前工作台是覆盖式弹窗，左栏会持续占用内容宽度；不保留单层折行按钮，因为它无法解决入口同权和分类不清的问题。

## 导航分组

### 概览

概览保持独立，不显示二级导航。它承载全局数量、自动沉淀状态、默认 Runtime 和数据目录摘要。

### Case 沉淀与管理

二级入口按 Case 从发现到持久化管理的流程排列：

1. 自动沉淀
2. Raw Case
3. Draft 审核
4. Case 与数据集
5. 数据集

这一组同时覆盖新 Case 的生产过程和已保存 Case 的日常维护，因此名称使用“Case 沉淀与管理”，而不是只写“Case 沉淀”。

### Skill 与安装

二级入口为：

1. Skill 管理
2. Runtime 安装

Skill 管理负责受管仓库、候选版本、发布版本和版本信息；Runtime 安装负责把已发布版本下发到 Runtime，并查看安装 Job 与可信安装审计。两者共同构成“准备版本 → 安装版本”的连续流程。

### 评测与优化

二级入口按质量闭环排列：

1. 评分标准
2. Skill 评测
3. 自操作与优化
4. 自动优化

评分标准先定义判断依据，Skill 评测产生得分和 Judge/Trace 证据，自操作承载人工引导的修订，自动优化承载多轮自动迭代。

## 交互规则

- 当前页面决定一级选中项和二级选中项；从工作台内部跳转到具体 Draft、Case、安装 Job 或评测运行时，分组状态随目标页面自动更新。
- 点击一级业务域时，进入该组默认页面：Case 沉淀与管理进入“自动沉淀”，Skill 与安装进入“Skill 管理”，评测与优化进入“评分标准”。
- 一级“概览”直接进入概览，不保留空的二级导航占位。
- 页面路由对象和深链参数保持不变，避免破坏从对话沉淀按钮、Draft、Case、安装 Job 和评测详情进入工作台的现有路径。
- 一级导航使用更明确的选中态；二级导航视觉权重较低，但继续使用现有 DSH Button primitive 和主题变量。
- 窄窗口允许一级与二级导航各自在自身行内换行，不允许两个层级混成同一排按钮。

## 移除旧版入口

正式界面移除“导入旧版 Electron 数据”和“诊断”两个入口：

- 工作台不再声明 `import` 和 `diagnostics` 路由，也不再渲染对应一级或二级按钮。
- Settings 不再显示旧版 Electron 导入面板；普通发行用户不会看到旧版产品概念。
- Settings 中重复的“诊断”标题卡片移除；默认 Runtime 仍由可编辑设置直接体现，数据目录仍可在概览中查看。
- 底层 `legacyImport.status`、`legacyImport.run` 和迁移实现暂时保留，避免本轮信息架构改动顺带删除恢复能力；它们不再有普通用户入口。
- `ImportPanel` 文件可以保留为未接入组件，后续确认不再需要迁移能力时再连同 Core API 和测试单独删除。

## 错误与状态行为

导航重构不改变工作台加载、重试或业务错误处理。Dashboard 加载失败时仍显示统一错误态；某个二级页面的错误继续由该页面自身处理。切换一级或二级入口不会清除 Durable 数据，也不会触发额外迁移、安装或评测操作。

## 测试与验收

- 源码测试证明所有现有业务页面恰好归属一个可见分组，概览独立，旧版导入和诊断不再出现在工作台或 Settings。
- 路由测试证明带 `sessionId`、`datasetId`、`caseId`、`jobId`、`runId` 的内部跳转仍选择正确分组和页面。
- DSH Client 构建与插件包检查通过。
- 安装新版本到本机 web profile 后，在真实 DSH 浏览器中确认：一级只显示四个入口；业务组只显示对应二级入口；切换与深链正常；旧版导入和诊断对普通用户不可见。

## 非目标

- 不删除 Core 里的旧版迁移数据结构和 API。
- 不改变工作台各业务面板内部表单、按钮、模型设置或执行流程。
- 不重命名 Durable 路由、数据记录或 Host API 方法。
- 不把工作台改成左侧导航、命令面板或首页卡片式入口。
