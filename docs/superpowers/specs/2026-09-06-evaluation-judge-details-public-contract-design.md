# 评测 Judge 详情公共契约设计

## 问题

评测结果在本地存储中包含统一评分项、Judge 逐项理由和实际模型信息，但 `evaluations.get` 的公共映射只返回总分和摘要。Renderer 因缺少 `computedScore.criterionScores` 而误走旧版评分分支，并因缺少 Skill 绑定与 Judge 配置而显示错误的“仅诊断”和“运行时默认模型”。

## 设计

`evaluations.get` 返回界面展示所需的结构化评分详情：安全裁剪后的评分契约条目、程序计算的逐项得分、Judge 逐项评价、实际 Judge/目标 Runtime 配置和 Skill 绑定状态。继续禁止返回目标回答正文、Judge 会话身份、Trace 路径、执行文件路径和证据原文。

列表接口仍只返回摘要；只有单条详情读取返回上述字段。现有 Renderer 无需改变分支逻辑，拿到统一评分数组后会直接显示“Judge 与评分明细”。

## 错误与兼容

缺失、越界或格式不合法的可选详情字段会被公共映射丢弃，不影响总分展示。旧版评测没有统一评分数组时仍使用旧版只读展示。

## 验证

通过控制面回归测试证明：新格式详情保留评论及模型/绑定信息，同时原始回答、Trace、Judge thread 和评分证据原文仍不可见；再用 Renderer smoke 与安装版 App 打开当前自动优化基线评测验证真实界面。
